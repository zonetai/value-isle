## 任務

任務：更新「價值島」網站的每日觀測資料，並推上 GitHub。全程使用繁體中文。只改一個檔案：data/daily.ts。不要改網站其他任何檔案。

專案資料夾（git repo，遠端 origin = https://github.com/zonetai/value-isle.git，分支 main）：
（請換成這台電腦上 value-isle 的實際路徑；這個資料夾固定停在 main 分支，專供本排程使用。若 git branch --show-current 不是 main，就停下來回報，不要切換分支或做任何修改。）

網站是「中泰不動產智庫」給一般大眾看的公開網站，正式網址 https://zonetai.com/value-isle/daily（官網轉接 Vercel，推上 main 後約 2 分鐘內更新），立場中立。價格分四層：intl 國際海象、policy 政策氣候、market 市場潮位、ind 個別條件。
用詞禁忌：全站不使用「洋流」一詞（敏感），任何新增文字都不要出現這兩個字；國際這一層一律稱「國際海象」。每則快訊的 layer 務必標對，因為各層頁面會自動取用對應 layer 的內容。

步驟：
0. 先同步：在專案資料夾執行 git pull --ff-only origin main。網站的版面與其他資料檔會由別台電腦更新，不先同步會推送失敗。pull 失敗（例如本機有未提交的變更）就停下來回報，不要強制覆蓋。
1. 用 Read 讀 data/daily.ts，了解 DAILY 的結構：updated、schedule、outlook（情境推演的目前方向）、topics（專題）、briefs（每日快訊，由新到舊）。記下已有的 briefs，避免重複。
2. 用 WebSearch 搜尋「過去 24 至 48 小時」的新聞（今天日期以系統日期、臺北時間為準），四類各找：
   - intl：聯準會與美國利率、美股與臺股、新臺幣匯率、美國關稅與對臺經貿、美國期中選舉後的國會與財政進展、油價與通膨、臺灣出口與景氣燈號。
   - policy：臺灣央行理監事會與信用管制、財政部與內政部的房市／稅制／貸款政策、都更與危老條例修法進度、社宅與租金補貼；2026-11-28 九合一選舉前為各縣市候選人的住宅、都更、捷運、產業用地、重劃與公有地政見；選後改為當選人相關政見的落實、預算與人事。
   - market：六都買賣移轉棟數、房價指數、預售與新案、法拍、租金、商用不動產交易、營建成本。
   - ind：具體的都更案、公辦都更、重大建設動工或通車、嫌惡設施或災害事件等「個案層級」且有估價意義的新聞。
3. 從中挑 4 到 8 則最有估價意義的，每則必須用 WebFetch 或搜尋結果確認「日期、數字、出處」後才寫入。寫成 briefs 物件，加在陣列最前面：
   { d: "YYYY-MM-DD"（新聞日期）, layer: "intl|policy|market|ind", tag: "2 至 6 字主題", t: "標題 24 字內，含關鍵數字", s: "一句事實，60 字內", i: "對估價的影響，一句 45 字內，用估價語言（一般因素、區域因素、個別因素、折現率、比較法、成本法、期日修正等）", src: "媒體或機關名", url: "原文網址" }
   若當天真的沒有值得寫的新聞，可以少於 4 則，但不要湊數。
4. 寫作規則（務必遵守）：
   - 中立：只陳述事實與各方公開說法，不預測選情、不引用民調、不評論任何政黨或候選人好壞；涉及選舉的條目，同一議題盡量平衡呈現不同陣營，並用「主張」「稱」「表示」等中性動詞。
   - 每則都要有 src 與 url；找不到可開啟的原文就不要寫。數字以原文為準，不自行推算。
   - 不寫投資建議、不喊漲跌；「對估價的影響」只說傳導方向與估價上怎麼處理。
   - 不得出現任何事務所客戶、個案當事人、未公開資料；不寫個人姓名（例如寫「央行總裁」，不寫名字）。
   - 數字用阿拉伯數字；不用「——」；不用「首先、其次、綜上所述、值得注意的是」。
   - 網站任何地方都不要提到本站參考過其他網站。
5. 維護：
   - briefs 最多保留 60 則，並刪除日期早於 45 天前的條目。
   - 把 updated 改成今天日期（YYYY-MM-DD）。
   - outlook（首頁「如果…」情境推演的「目前方向」，不得刪除）：結構為 { updated, note, items: { cut, hike, credit, export, mrt, supply } }，每一項是 { lean, now, why:[…], basis:[{ t, d, src, url }] }。lean 只能填「正在發生／已發生／較可能／可能性各半／較不可能」其中之一。只有出現會改變判讀的新資料時才更新（央行理監事會決議、聯準會決議、CPI、出口與外銷訂單統計、信用管制或新青安調整、捷運通車或延期公告、使用執照與買賣移轉棟數統計）：把新資料加在該項 basis 最前面（每項最多 5 則，t 40 字內，必附 d、src、url），必要時改寫 now（60 字內）與 lean，並把 outlook.updated 改成今天。沒有新資料就不要動。判讀只根據 basis 列出的事實，寫清楚理由，不喊漲跌、不寫投資建議；數字以原文為準。
   - topics：若「us-midterm」或「tw-local」專題內的事實有重大更新（例如席次定案、聯準會決議、法案三讀、選舉結果出爐），就更新對應的 status、groups／themes 內的條目與 watch，並保留來源。2026-11-28 投票日之後，把 tw-local 的 title 改為「九合一選後的住宅與土地政策追蹤」、status 改寫為選後狀態，themes 的 positions 逐步改為當選人的政見與落實進度（落選者的主張可刪）。專題已無新進展超過 30 天時，可在 status 註明「本專題已停止更新」，但不要刪除。
   - 用 Edit 或 Write 工具修改檔案，不要用 shell 的 heredoc 寫入中文內容。保持檔案開頭的註解、import type 那一行與 export const DAILY: DailyData = {...}; 的格式。
6. 驗證：在專案資料夾執行 npm run check:daily（第一次執行前若沒有 node_modules，先跑 npm install）。必須印出今天日期、則數與「檢查通過」；它也會檢查 outlook 的每一項都有 lean、now 與附出處的依據。失敗就修到通過；修不好就用 git checkout -- data/daily.ts 還原並回報錯誤，不要推送壞檔。
7. 提交與推送（在專案資料夾內）：
   git add data/daily.ts
   git commit -m "每日觀測 YYYY-MM-DD"
   git push origin main
   若沒有任何變更就不要提交。push 被拒（遠端有新提交）時，先 git pull --rebase origin main 再推一次；仍失敗就回報錯誤訊息（常見原因是 GitHub 登入過期，需要重新執行 gh auth login）。不要用 --force。
8. 回報：用兩三句話說明今天新增幾則、各層幾則、outlook 與專題有沒有更新、是否已推送成功。

週期性產出規約：落點 data/daily.ts（單一檔案就地更新）；保留期限 45 天、60 則；版本由 git 歷史保存。

# 權變沙盤｜架構書（第一版草案）

價值島第二個姊妹站。一句話：**把自己家的條件填進去，看估價師怎麼算分回。**

- 資料夾：`renewal-sandbox/`（與 `far-payment/` 平行）
- 線上位置：`https://zonetai.com/value-isle/renewal-sandbox/`
- 署名：中泰不動產智庫；導覽列右側「回價值島」，與代金學堂相同

---

## 壹、定位

### 一、要解決的問題

都更的爭議九成集中在三句話：「我家為什麼比隔壁少」「共同負擔為什麼這麼高」「分回來的坪數為什麼不夠」。市面上的說明不是只講流程，就是把數字藏在劇情裡。這個站把權利變換的計算鏈攤開，讓人用自己的條件走一遍。

### 二、服務對象（三條路線，首頁三個入口）

| 路線 | 對象 | 進站後第一個動作 |
|---|---|---|
| 地主 | 住戶、持分人、繼承人 | 填自家土地坪、建物坪、樓層，看三情境分回 |
| 實施者 | 建商、地主自組更新會 | 填基地與更新後假設，看共同負擔與分回比例能不能過審 |
| 審查者 | 審議委員、公會協檢、同業 | 直接開審查視角頁，用檢核清單對報告 |

### 三、與現有兩站的關係

| | 價值島 | 代金學堂 | 權變沙盤 |
|---|---|---|---|
| 性質 | 觀測站 | 學堂加試算 | 工具加審查視角 |
| 主角 | 市場數字 | 容積代金公式 | 權利變換分配 |
| 更新 | 每日 | 不定期 | 每月（核定案數據） |
| 共用 | 圖示庫、紙色視覺、中文小標 | `common.js` 的導覽、頁尾、上下站、進度、toast 模式 | — |

## 貳、區隔原則（刻意不做的事）

同業已有一款以「走訪鄰居取得同意」為主軸的劇情遊戲。本站不走那條路，以下列為硬規則：

1. 不做角色扮演，不設鄰居、里長、估價師等擬人角色，不放人物畫像。
2. 不做街廓地圖、不做地號 A 到 H 圈選、不做 3D 場景。首頁視覺用「分配天平」或「計算鏈」的平面圖解，不用島、村、街。
3. 不做章節與任務制。結構是「路線」與「站」，與代金學堂相同。
4. 不用劇情口吻與家庭敘事標語。語氣沿用「一塊地的價格，從四層看起」的估價師視角。
5. 所有數字來自法規、主管機關範本、審議紀錄或使用者自己輸入，不用虛構人物與虛構案例。示範案用公開核定案的區間值組成，並標明「示範」。
6. 公開文字不提任何同業站名，不提「參考」來源。
7. 整站靜態、無框架、無 3D 模型，首載控制在 1 MB 內。

## 肆、各站內容規格

### 一、首頁 `index.html`

- 標題區：站名、一句話、三個入口按鈕（地主／實施者／審查者）。
- 計算鏈總圖：四個方塊橫排，更新前權值 A → 更新後總價 B → 共同負擔 C → 分回。方塊可點，跳到對應站。捲動時依序亮起，動畫沿用代金學堂的捲動顯示。
- 統計牆摘要：最近十二個月臺北市核定案的共負比中位數、更新後均價中位數、案件數，三個數字加一句判讀。資料來自 `data.js` 的 `cases`，由月報流程更新。
- 本月更新：列最近一次資料更新日期與新增案件數。

### 二、計算鏈 `chain.html`

把權利變換四個數字的關係講清楚，是全站的觀念基礎。

1. **更新前權利價值 A**：各戶權值 = 比準地價格 × 各宗調整率（相加）→ 合併增值係數 → 宗地價 → 依土地貢獻占比分到各戶；區分建物另有比準戶 × 效用比 → 土地貢獻價格 → 扣建物使用權 → 持分不一找補。用一張可展開的流程圖呈現，每一步附「為什麼要這一步」。
2. **更新後房地總價 B**：店面、住宅、車位分開估；樓層別效用比；市場支撐來自周邊新成屋成交。
3. **共同負擔 C**：工程費、管理費、貸款利息、稅捐、實施者利潤、其他；共負比 D = C ÷ B。
4. **分回**：地主分配價值 = B − C；各戶分回價值 = 各戶 A ÷ ΣA × (B − C)；分回坪數 = 分回價值 ÷ 選配單價；找補 = 選配價值 − 分回價值。
5. 小結：三個常見誤會。「A 值高就分得多」（錯，看的是占比）、「共負比低就划算」（不一定，看 B 值有沒有灌水）、「分回坪數是固定的」（錯，隨選配樓層變動）。

### 三、分回試算 `calc.html`（全站核心）

**輸入**，分三層，預設展開第一層：

| 層 | 欄位 | 預設 |
|---|---|---|
| 我家 | 土地持分坪、建物坪、樓層、用途（住宅／店面）、有無車位、所在宗 | 示範戶 |
| 基地 | 總土地坪、宗數、使用分區、法定容積率、獎勵容積率（含上限）、建蔽率、比準地單價 | 示範基地 |
| 更新後 | 樓層數、公設比、店面單價、樓上均價、車位單價、車位數、共同負擔各項（或直接填共負比） | 示範假設 |

**情境**：保守、基準、樂觀三欄並列。差異參數固定為三項：更新後均價（−10% ／ 0 ／ +10%）、共負比（+5 點／ 0 ／ −5 點）、獎勵容積（下限／中值／上限）。使用者可改。

**輸出**：

- 我家的 A 值、占全基地比例、分回價值、分回坪數（以選配樓層單價換算）、找補金額。
- 全基地的 B 值、C 值、共負比、地主分回樓地板比。
- 「這個數字怎麼來的」：每個輸出旁一個展開鈕，列出公式與代入值，與代金學堂試算器的「計算過程」區相同做法。
- 敏感度：拉動更新後均價、共負比、比準地單價，分回坪數即時變動，標出最敏感的一項。
- 檢核燈號：見「伍、檢核燈號」。

**分享與帶走**：

- 輸入值編碼進網址參數，複製連結即可重現。
- 列印樣式一頁 A4：輸入摘要、三情境結果、燈號、免責與日期。瀏覽器列印即是 PDF，不另做產檔。

### 四、共同負擔拆解 `burden.html`

- 費用項目表：工程費（結構／樓層／等級單價、物價指數基準日）、人事行政管理費、銷售管理費（依總銷級距分段）、風險管理費、信託管理費、貸款利息（計息期間）、稅捐、容積獎勵申請費、實施者利潤、其他。每一項三欄：怎麼算、提列上限或規則、常見問題。
- 規則庫 `RULES.tpe`：臺北市費用提列總表與工程造價要項，版本與生效日寫死在規則庫，換版本只改規則庫。新北市另開 `RULES.ntpc`，第二版補。
- 互動：使用者填各項金額或比例，顯示共負比、各項占比長條、燈號。
- 「公辦都更不得提列」「自主更新部分項目不得提列」以開關控制，開啟後對應項目直接鎖零並說明。

### 五、審查視角 `review.html`

把事務所審查方法論整理成外部可讀的版本，不含案件資訊。

1. 四件事判準：基礎資料是否正確、價格差異是否有理由、修正邏輯是否一致、分配結果是否公平可說服。
2. 八個核心提問，每題附「要對哪一張表」。
3. 退件常見點自檢表，依更新前 A 值、更新後 B 值、共同負擔、估價方法、分回公平、變更案六組，每組五到八條，可勾選，勾完顯示「尚有幾項未確認」。
4. 三家估價離散度的看法：差距多少該追問，追問什麼。
5. 變更案專區：變更了什麼，估價報告有沒有跟著改。

### 六、爭點與解法 `dispute.html`（第二版）

十個爭點，每個爭點三段：地主怎麼看、實施者怎麼看、估價上怎麼拆。

1. 我家為什麼比隔壁少
2. 一樓店面值多少
3. 頂樓加蓋算不算
4. 車位怎麼分
5. 土地持分與建物坪不成比例時怎麼找補
6. 共同負擔為什麼這麼高
7. 更新後均價是不是喊高了
8. 三家估價結果不一樣聽誰的
9. 變更案之後我的分回變少了
10. 不同意戶的權利怎麼處理

內容來源：審查與調解實務的通案整理，不引個案。

### 七、核定案數據 `cases.html`（第二版）

- 資料：臺北市都市更新審議會議程及紀錄（資料集 145803），由現有月報流程抽取案名、案件類型、共負比、更新後均價、決議摘要，寫入 `data.js` 的 `cases`。估價師事務所名稱不公開。
- 圖表：共負比分布（直方）、更新後均價分布（依行政區）、年度趨勢（折線）、共負比與均價散佈。做法沿用價值島「市場潮位」的長條生長與折線描繪。
- 篩選：行政區、年度、案件類型。
- 每筆案件列：會議日期、行政區、案件類型、共負比、均價、決議一句話，附公告連結。

### 八、判斷題 `quiz.html`（第三版）

二十題，型式沿用代金學堂。答錯顯示解析並連回對應站。

### 九、關於 `about.html`

資料來源清單、計算假設、規則庫版本、更新方式、免責。免責文字：本站為教學用一般性整理，試算結果不構成估價意見或審議依據，實際案件以三家估價報告與審議決議為準。

## 伍、檢核燈號（calc.html 與 burden.html 共用）

燈號三級：警示、提醒、通過。每個燈號四欄：標題、為什麼看這個、規則或區間、怎麼修。區間值標明是教學門檻還是法規規定。

| 代號 | 看什麼 | 規則或區間 | 級別 |
|---|---|---|---|
| burden_ratio | 共負比 | 30% 至 45% 為常見區間，超過 45% 要有強說明 | 警示 |
| mgmt_admin | 人事行政管理費 | 公辦都更不得提列 | 警示 |
| mgmt_sales | 銷售管理費 | 依總銷級距分段提列，不得整筆用最高級距 | 警示 |
| mgmt_risk | 風險管理費 | 得以上限提列，但要有實質風險承擔 | 提醒 |
| interest | 貸款利息 | 計息期間不超過工期，不含銷售期 | 警示 |
| shop_ratio | 店面與樓上單價倍數 | 1.5 至 2.0 為常態 | 提醒 |
| public_ratio | 公設比 | 28% 至 36% | 提醒 |
| floors | 容積率 ÷ 建蔽率 | 約等於樓層數 | 提醒 |
| floor_eff | 樓層別效用比 | 逐層遞增、方向一致，無電梯棟不得高樓層加分 | 警示 |
| settle_net | 找補淨額 | 全基地找補淨額應為零 | 警示 |
| a_spread | 各宗單價差異 | 差異要對得上臨路、容積率、角地等條件 | 提醒 |
| b_support | 更新後均價 | 要落在周邊新成屋成交的合理分位 | 提醒 |
| profit | 實施者利潤 | 與風險、出資、共擔比例相稱 | 提醒 |
| result | 地主分回樓地板比 | 低於 50% 時提醒檢視 B 值與 C 值 | 提醒 |

燈號文字避免「錯」「不合法」等定性用語，一律寫成「要有說明」「先查哪裡」。

## 陸、程式與資料結構

沿用代金學堂的拆法，四個檔案。

| 檔案 | 內容 |
|---|---|
| `assets/data.js` | `window.RS`：頁面清單、三條路線、示範基地與示範戶、燈號文字、爭點、核定案 `cases`、辭典、題庫、資料日期 |
| `assets/calc.js` | 計算引擎與規則庫分離。`RULES` 放各縣市費用提列規則與版本；`calcA(基地, 各戶)`、`calcB(更新後)`、`calcC(費用項目)`、`distribute(A, B, C, 選配)`、`scenarios(輸入)`、`check(輸入, 結果)` 回傳燈號陣列 |
| `assets/common.js` | 導覽、頁尾、上下站、進度、toast、網址參數編解碼、列印。從代金學堂複製後改站名與路線邏輯 |
| `assets/style.css` | 延續價值島與代金學堂的紙色、字型、間距；新增三欄情境表、燈號、列印樣式 |

圖示用 `../assets/icons.js` 的線條圖示，需要新圖示（天平、鏈、燈號）在那裡加。

`calc.js` 的輸入模型：

```
{
  city: "tpe",
  site: { landPing, lots: [{ id, ping, far, roadWidth, corner, adj }], bcr, farLegal, farBonus, baseUnit },
  units: [{ id, lot, landPing, bldgPing, floor, use, parking, pos }],
  after: { floors, publicRatio, shopPrice, resPrice, parkPrice, parkN, shopArea, resArea },
  burden: { construction, adminMgmt, salesMgmt, riskMgmt, trustMgmt, interest, tax, bonusFee, profit, other } | { ratio },
  pick: { floor, use, ping }
}
```

輸出模型：每戶 A 值與占比、ΣA、B、C、D、各戶分回價值、分回坪、找補、三情境、燈號、敏感度。

## 柒、視覺與文案

- 色彩、字型、圓角、間距全部延續價值島與代金學堂的 `style.css` 變數，不另開一套。
- 首頁主視覺：平面的「分配天平」或「四方塊計算鏈」線條圖，不用立體場景、不用地圖、不用人物。
- 小標用中文，不用英文標籤；圖示用自繪線條圖示，不用 emoji。
- 數字一律加千分位與單位；坪與平方公尺並列時以坪為主。
- 語氣：估價師在白板前講解的口吻。少用「首先、其次、總而言之」；句長參差；每頁開頭一句話講這頁要回答的問題。
- 每頁頁尾固定一句：試算結果不構成估價意見，實際案件以三家估價報告與審議決議為準。

## 捌、技術與效能目標

- 靜態 HTML、原生 JavaScript、無建置步驟，與現有兩站一致，GitHub Pages 自動發布。
- 首載 1 MB 內，無外部字型（沿用系統字型），無第三方腳本。
- Lighthouse 四項目標 90 以上，手機優先。
- 每頁加 canonical 與 github.io 的 noindex 腳本，與代金學堂相同。
- 網址參數分享：`calc.html?s=<base64 json>`；長度超過 2,000 字時改存 localStorage 並提示。
- 列印樣式 `@media print`：隱藏導覽與互動元件，一頁 A4。
- 改 `assets/` 後各頁 `?v=` 加 1。
